So three different mechanics already used: (1) one continuous line/shape
interpolating, (2) a mask revealing a fixed illustration, (3) discrete props
flying in from off-screen and assembling into a static scene. This run
deliberately uses a fourth, different kind of mechanic: **a single ground
plan that draws itself as blueprint linework, then gains colour and texture
in place** — nothing enters from off-screen and there is no clip-path mask
over one fixed image; instead the same authored shapes go from thin ink
outline to fully "built" fill/texture, and small elements (fence posts,
stepping stones, pergola posts) grow in place at their own already-drawn
positions rather than travelling in from elsewhere. See "The centrepiece"
below for the full breakdown.

It's also a different trade (landscaper/garden-builder, not pet care, a
chimney trade, or hairdressing), a different accent hue family (blueprint
blue, not green, orange-red, or wine), a different type pairing (Newsreader
+ Space Grotesk, neither used before, and not Inter), and a different
concrete spacing/radius scale (8/16/24/36/56/88/136/208, radius 2/8/16 —
noticeably sharper/less rounded than any previous run, a deliberate choice
tying to the "technical drawing" theme).

## Design decisions

- **Accent colour:** a blueprint/technical-drawing blue (`#2b5c8a`, darker
  variant `#1d3f5c` for the trust section and hover states). Chosen because
  it reads as precise and considered — like ink on a plan — which fits a
  business whose whole distinguishing trait is that it designs before it
  builds. It's a different hue family from all three previous runs (sage
  green, ember red-orange, wine/burgundy), and deliberately not the
  beige+brass "artisan" cliché or AI-purple. Illustration-only colours
  (stone tan, grass green, pond blue, timber brown) exist inside the SVG
  artwork itself but never compete with the one UI accent used for links,
  buttons and headings.
- **Type pairing:** Newsreader (a literary serif with real italics) for
  headings, Space Grotesk (a geometric, slightly technical sans) for body
  copy and the SVG's blueprint annotation labels. Neither font was used in
  any previous run (Fraunces + Work Sans, Bricolage Grotesque + Karla,
  Frank Ruhl Libre + Manrope), and neither is Inter.
- **Spacing/radius system:** an 8px-rooted but faster-growing scale
  (`--space-1` to `--space-8`: 8, 16, 24, 36, 56, 88, 136, 208px) and a
  three-step radius system deliberately sharper than any previous run
  (2px small elements, 8px cards, 16px large shapes) — a concrete,
  structural, drafting-table feel rather than the softer rounded corners
  used in all three previous sites, which fits a business about precise
  plans and hard landscaping rather than something cosier.

## The centrepiece (Step 4's "genuinely inventive moment")

**"From plan to planted."** A pinned, scroll-scrubbed SVG scene, built with
GSAP + ScrollTrigger, of a garden plot shown from directly above — a plan
view, like the "garden plans" this business actually draws up before
building anything. Every element is authored in the SVG at its *finished,
fully built* state (paved patio, green lawn, filled pond, standing fence
posts and pergola) so the page still looks correct and complete with no JS,
a blocked CDN, or reduced motion. On load, if motion is allowed, JS
displaces every element back to a "blank blueprint" starting state via
`gsap.set`, then a single scrubbed timeline drives it forward in the same
order the business would actually build a garden:

1. The plot boundary draws itself as a thin ink line (`stroke-dashoffset`),
   over a visible graph-paper grid — this is the "plan" stage.
2. The patio outline draws in, a "PATIO · 5.4 × 3.2m" label fades in like a
   real drawing annotation, then the outline fills with a paver texture and
   the label fades back out — the plan becoming a built surface.
3. A "FENCE LINE" label appears, and a row of small fence-post markers
   scale up in place, staggered, directly on the already-drawn boundary
   line — nothing travels in from outside the frame, each post simply grows
   at the exact spot it was always drawn to occupy.
4. The lawn area (already outlined from the start) fills with green and a
   scatter of small grass-tick marks fades in.
5. A path draws itself from patio to pond, and a run of stepping-stone
   ellipses pop into place along it, staggered.
6. A "POND" label appears, the pond outline draws, fills with a water
   gradient, and three ripple rings scale outward — then the label fades.
7. A small pergola's corner posts scale up and its roof beams draw in.
8. The background grid fades down from a strong blueprint-paper opacity to
   a faint trace, and a warm sun-glow fades in — the plan has become a
   finished, sunlit garden.

Four captions ("01 The plan", "02 The structure", "03 The planting", "04
The finish") crossfade in time with the same timeline progress.

This is deliberately a different *kind* of moment from all three previous
runs: nothing is a single continuously-interpolating line or shape (unlike
the pulse line), there is no clip-path mask sliding over one fixed
illustration (unlike the soot reveal), and nothing enters the scene from
off-screen to assemble into a static tableau (unlike the kit-bag unpacking).
Instead, one fixed set of shapes — always in the same place — transitions
from thin outline to full, textured, coloured "built" form, and the only
things that grow into position (fence posts, stepping stones, pergola
posts) do so exactly where they were always drawn, not from elsewhere. It's
a literal visualisation of what actually makes this business distinctive:
they draw the plan first, then build exactly that.

## Mobile and reduced-motion handling

- `prefers-reduced-motion: reduce` is checked before anything else. If set,
  the page adds a `no-motion` class (forcing every `.reveal` element
  visible via CSS) and returns immediately without building any GSAP
  timeline — the SVG is already authored in its finished, built state by
  default, so nothing further is needed there. The same CSS rule is
  duplicated as a plain `@media (prefers-reduced-motion: reduce)` block, so
  it still applies even in a hypothetical future refactor that stops adding
  the JS class.
- A second, independent fallback (learned directly from a real bug caught
  in the Hair, There & Everywhere run's own testing) checks
  `typeof window.gsap === 'undefined'`. If the GSAP CDN script fails to
  load or execute at all, the page adds a `no-gsap` class with the same
  "show everything" CSS override, instead of leaving `.reveal` elements
  stuck at `opacity:0`.
- On viewports at or below 760px, `ScrollTrigger.matchMedia` swaps the
  centrepiece from a pinned scrub (`pin: '.cp-sticky'`, `end: '+=380%'`) to
  an unpinned one (`pin: false`, `end: 'bottom bottom'`), so the same
  timeline still plays out as the visitor scrolls naturally past the
  section instead of hijacking touch scroll.

## Testing

cdnjs.cloudflare.com is blocked in this sandbox for both `curl` and
headless-browser traffic, same as every previous run, so the real
GSAP/ScrollTrigger animation could not be watched playing against the real
CDN files in this environment. To still catch real bugs before shipping, I
used Playwright with the sandbox's pre-installed Chromium:

1. Rendered the actual page with the real (blocked) GSAP `<script>` tags
   present — confirms the `no-gsap` fallback path works exactly as a real
   visitor with a failed/blocked CDN would experience it: full content
   visible, no elements stuck at `opacity:0`, no console errors.
2. Served a small local stub of the `gsap`/`ScrollTrigger` API (`.set`,
   `.timeline().to()`, `.registerPlugin`, `.utils.toArray`,
   `ScrollTrigger.matchMedia`) via Playwright request interception in place
   of the real CDN files, and ran the real, unmodified script against it —
   confirms every element ID and selector the script references
   (`#cpBoundary`, `#cpPatioOutline`, `#cpFencePosts rect`, etc.) genuinely
   exists in the page, and that the timeline builds without throwing.
3. Checked `prefers-reduced-motion: reduce` directly via Playwright's
   `emulateMedia` — confirms every `.reveal` element and the centerpiece
   are visible immediately with no script needed.
4. Full-page screenshots at 1300px and 390px widths, in both the
   no-GSAP-fallback and reduced-motion states, confirmed no horizontal
   overflow and no overlapping/clipped text in any section (hero, essence,
   centrepiece, services, trust, closing CTA, footer).
